# «Код ізі» жүйесінің техникалық сипаттамасы

Авторлық құқықпен қорғалатын объектіге (ЭЕМ бағдарламасына) куәлік алу өтініміне арналған.

| | |
| --- | --- |
| Объектінің атауы | «Код ізі» — C++ бойынша студент білімін бақылау және олимпиадаға дайындау веб-жүйесі |
| Объектінің түрі | ЭЕМ-ге арналған бағдарлама (веб-қосымша) |
| Авторлар | [өтініш берушінің деректері: аты-жөні, ұйымы] |
| Құқық иеленуші | [өтініш берушінің деректері] |
| Негізі | Жаксылыков, диссертация «Программалаудан студенттердің білімін бақылаудың интеллектуалдық моделі» |
| Бағдарламалау тілдері | Python 3.12, TypeScript, SQL, C++ (тапсырмалардың эталон шешімдері) |
| Бастапқы код | `asetzhan/kod-izi` репозиторийі |

## 1. Мақсаты

Жүйе программалаудан студенттердің білімін бақылаудың интеллектуалдық моделін іске асырады. Модель бес компоненттен, ядродан және GenAI платформасынан тұрады. Жүйе:

- C++ тапсырмаларын қорғалған ортада тестілейді;
- код жазу үдерісін (цифрлық ізді) жазады;
- жұмысты курс кітабына сүйене отырып, алты критерий бойынша AI арқылы алдын ала бағалайды, соңғы бағаны оқытушы қояды;
- студенттің білім моделін жүргізеді;
- олимпиадаға дайындыққа арналған жарыстарды өткізеді.

## 2. Пайдаланушылар

Студент, оқытушы, жаттықтырушы, әкімші. Әр рөлдің құқығы серверде тексеріледі. Сонымен қатар дерекқор деңгейінде жол деңгейіндегі қауіпсіздік (RLS) қолданылады.

## 3. Құрамы

| Бөлік | Мазмұны |

| Фондық жұмысшылар | Тапсыруларды тестілеу және AI-бағалау (`worker`); материалдарды өңдеу, антивирус және OCR (`extractor`); кодтың ұқсастығы (`analyzer`, JPlag); сыртқы платформалар (`connector`, Codeforces) |

## 4. Архитектурасы

```
Браузер ──HTTPS── Nginx ──► frontend (React)
                    └────► backend (FastAPI) ──► PostgreSQL + pgvector, Redis
                                  │
              RQ кезектері ───────┼──► worker   ──► Judge0 (желісіз құм жәшігі), Ollama
                                  ├──► extractor ──► ClamAV, Tesseract (kaz, rus)
                                  ├──► analyzer  ──► JPlag (интернетсіз)
                                  └──► connector ──► Codeforces API (тек студенттің келісімімен)
```

- Веб-деңгей интернетке шықпайды.
- Студенттің коды тек Judge0-де, желісіз орындалады.
- Жергілікті LLM (Ollama) жеке желіде тұрады, студенттің деректері шетелдік API-ге жіберілмейді.
- Әр жұмысшыға тек өз міндетіне керек желі мен құқық берілген.

## 5. Негізгі алгоритмдер

### 5.1. Тапсырма деңгейі

Тапсырманың төрт белгісі бар: білім мен әрекеттердің саны, алгоритмді таңдау еркіндігі, шеттік жағдайлар, шешімді негіздеу. Әр белгі 0–2 балмен бағаланады. Деңгей балдардың қосындысынан шығады: 0–2 → I, 3–4 → II, 5–6 → III, 7–8 → IV. Шектері баптауда тұр. Пилоттан кейін тапсырманың нақты шешілу үлесі деңгейдің эталонымен салыстырылады, айырмашылық шектен асса, тапсырма қайта қарауға белгіленеді.

### 5.2. Тестілеу және цифрлық із

Тапсыру жасырын тесттердің бәрінде Judge0 арқылы тексеріледі. Вердиктер: OK, WA, TLE, MLE, RE, CE.

Цифрлық із тек толығатын кестеде сақталады. Оған код снапшоттары, қою, терезеден шығу, іске қосу, тесттер және AI сұрақтары жазылады.

Әр оқиға программалау әрекетінің кезеңімен белгіленеді: түсіну, жоспарлау, кодтау, тестілеу, түзету, түсіндіру. Белгілеу ережелер бойынша жасалады: компиляция қатесінен кейінгі өзгеріс — түзету, бірінші іске қосуға дейінгі түсініктемелік код — жоспар.

Үдеріс көрсеткіштері: әрекеттер саны, компиляция қателерінің түрлері мен қайталануы, түзетуге кеткен уақыт. Оқытушы код жазу үдерісін уақыт шкаласы бойынша қайта ойнатады.

### 5.3. AI көмегімен алдын ала бағалау

LLM-ге төмендегі деректердің бәрі `<data>` блоктарымен, нұсқау ретінде емес, дерек ретінде беріледі:

- тапсырма, рубрика, тест нәтижелері, статикалық талдау (clang-tidy, cppcheck);
- үдеріс көрсеткіштері, студенттің коды мен түсіндірмесі, AI сұхбаты;
- оқытушы бағалаған үлгі жұмыстар;
- курс кітабынан мағыналық іздеу (pgvector) арқылы табылған үзінділер.

LLM алты критерий бойынша деңгей (low, mid, high) қойып, әр дәлелге кітаптан сілтеме береді. F, E, A компоненттері (0–100) рубрика салмақтарымен жалпы балға біріктіріледі.

Жауап JSON сызбасы бойынша тексеріледі. Жауап жарамсыз болса, сұрау бір рет қайталанады. Prompt injection белгілері табылса, жұмыс оқытушыға белгіленеді. Студент AI бағасын оқытушы растағаннан кейін ғана көреді.

AI мен оқытушы бағасының сәйкестігі Pearson, Spearman, MAE және MD коэффициенттерімен есептеледі.

### 5.4. Студенттің білім жағдайы

**Беспалько коэффициенті:** K = a / p, мұндағы a — тақырыптың берілген деңгейінде толық орындалған тапсырмалар (бірде-бір критерий «төмен» емес), p — сол деңгейде берілген тапсырмалар. K ≥ 0,7 болса, деңгей меңгерілген.

**BKT (Bayesian Knowledge Tracing).** Әр білім компоненті үшін P(L) ықтималдығы әр әрекеттен кейін жаңарады.

Дұрыс әрекеттен кейін:

  P(L|дұрыс) = P(L)(1 − s) / [P(L)(1 − s) + (1 − P(L))g]

Қате әрекеттен кейін:

  P(L|қате) = P(L)s / [P(L)s + (1 − P(L))(1 − g)]

Содан кейін меңгеру ескеріледі: P(L) ← P(L|·) + (1 − P(L|·))·t.

Мұндағы s — қателесу (slip), g — болжап табу (guess), t — меңгеру (transit) ықтималдығы. Параметрлер курс деректері бойынша ең үлкен шындыққа ұқсастық әдісімен бағаланады. P(L) ≥ 0,95 болса, компонент меңгерілген.

**Code-DKT.** Бұл LSTM моделі. Кірісі: білім компоненті мен дұрыстықтың one-hot векторы және кодтың 44 белгісі (12 метрика және токендер жұптарының хэштелген гистограммасы). Модель келесі әрекеттің дұрыстығын болжайды.

Модель тек нақты деректерде оқытылса және ROC AUC бойынша BKT-дан кемінде 0,02-ге жоғары болса қолданылады, әйтпесе жүйе BKT-ға қайтады. Симуляцияланған деректердегі салыстыру: BKT AUC 0,731, Code-DKT AUC 0,760 (`docs/reports/code-dkt-vs-bkt.md`).

**Келесі тапсырма** ең әлсіз критерий, меңгерілмеген компоненттер және меңгерілген деңгейден кейінгі деңгей бойынша таңдалады.

### 5.5. Олимпиада бөлімі

- **ICPC:** шешілген есептер саны бойынша, тең болса айыппұл бойынша реттеледі. Айыппұл — қабылданған әрекеттің минуты және одан бұрынғы әр қате әрекет үшін 20 минут. Компиляция қатесіне айыппұл жоқ.
- **IOI:** әр есептің ең жақсы тапсыруы ескеріледі. Ішкі есептің балы оның барлық тесті өткенде ғана беріледі.
- **Кестені тоқтату:** соңғы минуттарда кесте басқалар үшін тоқтатылады.
- **Виртуалды раунд:** басқа қатысушылар сол минуттағы күйімен көрсетіледі.
- **«Бір сағат» ережесі:** талдау есепке бір сағат жұмсалғаннан кейін ашылады. AI кеңестері біртіндеп ашылады (бағыт → идея → псевдокод) және код бермейді.
- **Стресс-тест:** генератор, баяу дұрыс шешім және студенттің шешімі Judge0-де салыстырылады.
- **Деңгейге сай ұсыныс:** студенттің рейтингінен +100…+300 жоғары есептер ұсынылады.

### 5.6. Кодтың ұқсастығы

Негізгі құрал — JPlag (C++). Қосымша, кірістірілген әдіс — winnowing:

1. Код токендерге бөлінеді, атаулар мен литералдар қалыпқа келтіріледі.
2. k-граммалардың хэштерінен әр терезенің ең кішісі алынады (саусақ іздері).
3. Ұқсастық — ортақ іздердің кіші жиынға қатынасы.

Айнымалылардың атын ауыстыру мен кодты қайта пішімдеу ұқсастықты жасыра алмайды.

## 6. Қауіпсіздік және дербес деректер

- **Кіру:** құпиясөздер Argon2id-пен сақталады. JWT токені қысқа мерзімді, refresh токендер ауыстырылып отырады. Оқытушы мен әкімшіге TOTP міндетті.
- **Дерекқор:** RLS қолданылады. Аудит журналы мен цифрлық із тек толығады.
- **Дербес деректер:** деректерді өңдеуге келісім алынады. Деректер белгіленген мерзімнен кейін анонимделеді, зерттеуде тек псевдоним қолданылады.
- **Материал файлдары** уақыт шектеулі, қол қойылған сілтеме арқылы беріледі.
- **Жүктелген файлдар** антивируспен тексеріледі және оқшауланған жұмысшыда өңделеді.
- **Резервтік көшірме** шифрланады, оның қалпына келтірілуі тестпен тексеріледі.
- **Тексеру:** әр әзірлеу кезеңі тәуелсіз қауіпсіздік шолуынан өтті (`docs/security/`).

## 7. Техникалық талаптар

**Сервер:**
- Linux, Docker Compose v2;
- 4 ядро, 16 ГБ RAM, 100 ГБ диск (Judge0 үшін cgroup v1 керек);
- жергілікті LLM үшін GPU ұсынылады.

**Клиент:** заманауи браузер.

**Жүктеме тесті:** 100 студент бір уақытта жұмыс істегенде тест нәтижесі ең көбі 3,1 секундта шықты, талап — 10 секунд (`docs/reports/load-test-2026-10-31.md`).

## 8. Сапасы

Барлық функционалдық талап (ФТ-01 – ФТ-49, ОТ-01 – ОТ-10) автотесттермен жабылған. Тесттер: сервер — 440-тан астам, интерфейс — 50-ден астам. Тест атауларында талаптың ID-і бар. CI (GitHub Actions) әр өзгерісте статикалық талдауды, типтерді, тесттерді, тәуелділіктердің осалдықтарын және құпиялардың ағуын тексереді.
