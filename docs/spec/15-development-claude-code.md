# 15. Claude Code арқылы әзірлеу

Жүйенің бүкіл кодын, тесттерін және техникалық құжаттамасын Claude Code жазады. Ол жұмысты осы техникалық тапсырма мен репозиторийдегі CLAUDE.md файлы бойынша жүргізеді. Талаптардың әрқайсысының тұрақты ID-і бар (ФТ-07, ОТ-04): Claude Code кодта, тестте және pull request сипаттамасында осы ID-лерге сілтейді.

## 15.1 Рөлдер

| Рөл | Кім | Жауапкершілігі |
| --- | --- | --- |
| Тапсырыс беруші | Диссертант | Техникалық тапсырманы бекітеді, кезеңдерді қабылдайды, педагогикалық мазмұнды (рубрика, деңгейлер, промпттар, тапсырмалар) тексереді |
| Әзірлеуші | Claude Code | Код, тесттер, дерекқор миграциялары, API құжаттамасы, орнату нұсқаулығы |
| Код шолушы | Тапсырыс беруші тағайындаған маман | Әр кезеңнің pull request-ін қарап, негізгі тармаққа біріктіреді |
| Инфрақұрылым | Университеттің IT бөлімі немесе тапсырыс беруші | Сервер, домен, құпия кілттер, резервтік көшірме |

## 15.2 Репозиторий құрылымы

```text
kod-izi/
├── CLAUDE.md            # Claude Code үшін тұрақты нұсқаулық
├── docs/spec/           # осы техникалық тапсырма, бөлімдер бойынша Markdown
├── backend/             # Python, FastAPI
│   ├── app/             # api, models, services, llm, analysis, judge
│   ├── migrations/      # Alembic
│   └── tests/
├── frontend/            # TypeScript, React, Monaco
│   └── src/             # pages, components, i18n (kk, ru)

└── .claude/

    ├── rules/           # backend және frontend ережелері
    └── agents/          # қауіпсіздікті шолушы субагент
```

## 15.3 CLAUDE.md мазмұны

CLAUDE.md әр сессияның басында жүктеледі, сондықтан онда тек тұрақты ережелер жазылады, көлемі 200 жолдан аспайды. Толық талаптар docs/spec ішінде сақталады. Бастапқы нұсқасы:

```markdown
# Код ізі
Веб-жүйе: C++ бойынша студент білімін бақылау және олимпиадаға дайындау.
Талаптар: docs/spec/. Терминдер: docs/spec/glossary.md.

## Стек
- backend: Python 3.12, FastAPI, SQLAlchemy 2, Alembic, PostgreSQL + pgvector, Redis, RQ
- frontend: TypeScript, React, Vite, Monaco
- кодты орындау: Judge0 (g++), бөлек серверде

## Командалар
- make dev: барлық сервисті docker compose арқылы іске қосу
- make test: pytest және vitest
- make lint: ruff, mypy, eslint, tsc

## Ережелер
- Әр функция ФТ немесе ОТ ID-іне сілтейді және кемінде бір автотестпен жабылады.
- Тесттерде нақты LLM API шақырылмайды: llm/ ішіндегі fake провайдер қолданылады.
- Дерекқор тек Alembic миграциясы арқылы өзгереді.
- Интерфейс мәтіндері тек i18n файлдарында (kk, ru).
- Модель компоненті жазбаларында source өрісі бар: auto, teacher, auto_edited.
- trace_events кестесі тек толығады, жолдар өзгертілмейді және өшірілмейді.
- AI бағасы студентке оқытушы растағанша көрсетілмейді.
- Рубрика, деңгей ережесі, промпт пен seed тапсырмаларын өзгертпес бұрын тапсырыс берушіден сұра.
- Талап түсініксіз болса, болжам жасама: сұрақты docs/spec/questions.md файлына жаз.

## Тыйым
- .env, құпия кілттер мен production баптауларын өзгертпе.
- Студент кодын Judge0-ден тыс орындама.
```

## 15.4 Міндетті қорғаныс тетіктері

CLAUDE.md-дағы нұсқау — талап, бірақ кепілдік емес. Сондықтан бұзылмауы тиіс ережелер техникалық тәсілмен бекітіледі:

- **PreToolUse hook.** .env, құпия кілттер мен production баптау файлдарын өзгертуді бұғаттайды.
- **PostToolUse hook.** Файл өзгергеннен кейін линтерді (ruff, eslint) іске қосады.
- **CI.** Әр pull request-те тесттер, линтер, тәуелділіктерді тексеру (pip-audit, npm audit) және құпия сканері іске қосылады. CI өтпесе, PR біріктірілмейді.
- **Қауіпсіздікті шолушы субагент.** Әр кезеңнің соңында кодты 14-бөлімдегі кесте бойынша тексеріп, есеп жазады.

## 15.5 Кезеңдер және қабылдау критерийлері

Кезеңдер ретімен орындалады. Келесі кезең алдыңғысы қабылданғаннан кейін басталады. Мерзімдер әр кезеңнің басында бекітіледі.

| Кезең | Claude Code не жасайды | Қабылдау критерийі |
| --- | --- | --- |
| 0. Каркас | Репозиторий, docker compose, CI, CLAUDE.md, hooks, аутентификация және төрт рөл | make dev бір командамен іске қосылады; әр рөлдің рұқсат тесттері өтеді |
| 1. Мазмұн | Курс пен тақырыптар, Stepik сабақтарының seed дерегі, тапсырмалар банкі, деңгей ережесі (5.2), ZIP импорты | 3- және 4-бөлімдегі барлық сабақ сілтемесімен жүйеде тұр; деңгей ережесі шеттік мәндермен тестіленген |
| 2. Ядро | C++ редакторы, Judge0 арқылы тестілеу, цифрлық із, түсіндірме | Эталон және қате шешімдер күтілген вердикт алады; бақылау жұмысын басынан аяғына дейін қайта ойнатуға болады |
| 3. Талдау | Статикалық талдау, LLM шлюзі, рубрика, кітап жүктеу және кітап негізінде бағалау, prompt injection-нан қорғаныс | LLM жауабы JSON сызбасынан өтеді; injection жиынтығында баға өзгермейді; әр дәлелде кітап сілтемесі бар |
| 4. Оқытушы панелі | Бес компоненттің панелі (6-бөлім), бағаны растау, кері байланыс, Беспалько коэффициенті | Әр компонент автоматты толтырылады; оқытушы өзгерткен мән қайта генерациялауда сақталады; нұсқалар тарихы жұмыс істейді |
| 5. Пилотқа дайындық | 14-бөлімдегі қауіпсіздік шаралары, жүктеме тесті, орнату нұсқаулығы | 16-бөлімдегі барлық тексерулер өтеді; тәуелсіз ену тесті жүргізілген |
| 6. 2-кезең | Олимпиада бөлімі (4 және 10-бөлімдер), BKT, ұсынымдар, OCR, JPlag | «2-кезең» деп белгіленген ФТ мен ОТ талаптары тесттерден өтеді |
| 7. 3-кезең | Code-DKT, жарыстан кейінгі AI талдауы, Codeforces интеграциясы, білім картасы | «3-кезең» деп белгіленген талаптар тесттерден өтеді; авторлық куәлікке өтінім дайындалады |

Пилот 5-кезеңнен кейін бір семестр бойы 1–2 топта өтеді. Оның нәтижесі бойынша деңгей ережесі мен шектік мәндер нақтыланады.

## 15.6 Жұмыс тәртібі

1. Әр кезеңнің басында Claude Code жоспар ұсынады: қай ФТ мен ОТ орындалады, қандай файлдар мен кестелер өзгереді, қандай тесттер жазылады. Тапсырыс беруші жоспарды бекітеді.
2. Әр кезең бөлек тармақта (branch) жасалады және pull request ретінде ұсынылады. Сипаттамада орындалған талаптардың ID-лері мен тексеру нәтижесі көрсетіледі.
3. Педагогикалық мазмұн — рубрика, деңгей белгілері, промпттар, seed тапсырмалары — тапсырыс берушінің растауымен ғана өзгереді.
4. Талап түсініксіз немесе құжаттар бір-біріне қайшы болса, Claude Code болжам жасамайды: сұрақты docs/spec/questions.md файлына жазып, тапсырыс берушіден жауап күтеді.
5. Кезең қабылданғаннан кейін CLAUDE.md жаңартылады: жаңа командалар мен қайталанған қателерден шыққан ережелер қосылады.
