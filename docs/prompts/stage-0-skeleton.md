# 0-кезең: каркас

**Алдын ала шешілетін сұрақтар:** Q-02 (репозиторий), Q-03 (Moodle/Platonus арқылы кіру).
**Қалай беру керек:** жаңа сессия, жоспарлау режимі (plan mode). Жоспарды оқып, бекіткеннен кейін ғана жұмысқа жіберіңіз.

```text
Сен «Код ізі» жүйесін әзірлейсің. Алдымен мына файлдарды оқы: CLAUDE.md,
docs/spec/README.md, docs/spec/02-roles.md, 11-architecture.md,
13-non-functional.md, 14-security.md, 15-development-claude-code.md,
docs/spec/questions.md.

Тапсырма: тек 0-кезеңді орында — жобаның каркасы. Келесі кезеңдердің
функцияларын жазба.

Нәтиже:
1. Репозиторий құрылымы 15.2-бөлімдегідей: backend, frontend, infra, seed,
   docs, .claude.
2. docker compose: PostgreSQL (pgvector кеңейтуімен), Redis, backend, frontend,
   Nginx, Judge0. Judge0 бөлек желіде, сыртқы желіге шықпайды, нұсқасы 1.13.1
   немесе жаңарақ.
3. Makefile: dev, test, lint, seed командалары.
4. Backend: FastAPI, health endpoint, SQLAlchemy 2 + Alembic, бастапқы миграция
   (User, Group, AuditLog). Баптаулар тек ортаның айнымалыларынан; .env.example.
5. Аутентификация: пайдаланушыны әкімші қосады; кіру; қысқа мерзімді access JWT
   және кері қайтарып алуға болатын refresh токен; құпиясөз Argon2id; кіру
   әрекеттерінің санын шектеу.
6. Төрт рөл: student, teacher, coach, admin. Рұқсаттарды тексеретін ортақ
   тәуелділік. Студент тек өз деректерін, оқытушы тек өз топтарын көреді.
7. Аудит журналы: кіру, шығу, рөл өзгерісі жазылады.
8. LLM шлюзінің интерфейсі және fake провайдер (нақты провайдерлер 3-кезеңде).
9. Frontend: Vite, React, TypeScript; i18n (kk, ru); кіру беті және әр рөлдің
   бос кабинеті.
10. CI: lint, test, pip-audit, npm audit, құпия сканері.
11. .claude/settings.json: PreToolUse hook .env, құпия кілттер мен production
    баптау файлдарын өзгертуді бұғаттайды; PostToolUse hook өзгерген файлға
    линтер іске қосады. .claude/agents/security-reviewer.md — 14-бөлімдегі
    кесте бойынша кодты тексеретін субагент.
12. README.md: орнату және іске қосу нұсқаулығы (қазақша).

Қабылдау критерийі:
- `make dev` таза машинада бір командамен бәрін көтереді.
- `make lint` пен `make test` өтеді, CI жасыл.
- Әр рөлге рұқсат тесттері бар: студент басқа студенттің дерегін сұраса 403.
- Hook .env файлын өзгертуді шынымен бұғаттайтыны тексерілген.

Q-02 немесе Q-03 шешілмеген болса, болжам жасама: жергілікті аутентификация
жаса, сыртқы кіру (SSO) үшін кеңейту нүктесін қалдыр және жоспарда атап көрсет.

Алдымен жоспар ұсын: файлдар, кестелер, endpoint-тер, тесттер, ашық сұрақтар.
Мен бекіткеннен кейін ғана код жаз.
```

**Қабылдағанда өзіңіз тексеретініңіз:** `make dev` іске қосылып, төрт рөлмен кіруге болады; CI жасыл; жоба README-і бойынша басқа компьютерде іске қосылады.
