# Әкімшіге арналған нұсқаулық

Әкімші бүкіл жүйеге жауап береді:

- пайдаланушыларды, топтарды және рөлдерді басқарады;
- баптауларды өзгертеді;
- аудит журналын қарайды;
- резервтік көшірмені бақылайды.

Жүйеге кіру және телефондағы код (2FA) [ортақ нұсқаулықта](README.md) жазылған. Әкімшіге 2FA міндетті.

> **Маңызды: әкімші беті әлі жасалмаған.** «Әкімші кабинеті» қазір бос, онда «Бұл бөлім келесі кезеңдерде толтырылады» деп жазылған. Әкімшінің барлық мүмкіндігі жүйенің сервер бөлігінде (API) бар, бірақ оларға арналған батырмалы беттер әлі жоқ. Сондықтан қазір әкімші жұмысын төмендегі командалармен немесе API арқылы жасайды. Бұл нұсқаулық не істеуге болатынын және оның қалай істелетінін айтады.

## 1. Бірінші әкімшіні жасау

Мұны жүйе орнатылған серверде бір рет жасайды:

```
make create-admin EMAIL=admin@university.kz
```

Команда құпиясөзді сұрайды. Құпиясөз ешбір файлға жазылмайды.

## 2. Әкімшінің мүмкіндіктері

| Не істеуге болады | Қалай (API) |
| --- | --- |
| Пайдаланушы қосу | `POST /api/admin/users` |
| Пайдаланушылар тізімі | `GET /api/admin/users` |
| Рөл беру (студент, оқытушы, жаттықтырушы, әкімші; бір адамда бірнеше рөл болуы мүмкін) | `PUT /api/admin/users/{id}/roles` |
| Топ құру | `POST /api/admin/groups` |
| Топқа студент қосу | `POST /api/admin/groups/{id}/members` |
| Топқа оқытушы қосу | `POST /api/admin/groups/{id}/teachers` |
| Курсқа топты байлау | `POST /api/courses/{id}/groups` |
| Курсқа оқытушы қосу (адамның оқытушы рөлі болуы керек) | `POST /api/courses/{id}/teachers` |
| Оқытушының телефоны жоғалса, 2FA-ны өшіру | `POST /api/admin/users/{id}/2fa/reset` |
| Пайдаланушының дербес деректерін анонимдеу | `POST /api/admin/users/{id}/anonymize` |
| Аудит журналы: кім, қашан, не істеді | `GET /api/admin/audit-log` |
| Баптаулар: деңгей ережесі, меңгеру шектері, адалдық белгілері, BKT, шешілу үлесі | `PUT /api/settings/...` |

API-дің толық сипаттамасы әзірлеу ортасында `http://<мекенжай>/api/docs` бетінде ашылады.

## 3. Күнделікті жұмыс

### 3.1. Жаңа семестр

1. Студенттер мен оқытушыларды қосыңыз.
2. Топтар құрып, оларға студенттер мен оқытушыларды қосыңыз.
3. Курсқа топты байлаңыз. Сонда студенттер курсты көреді.
4. Олимпиада курсының жаттықтырушысына **оқытушы** рөлін қосымша беріп, оны сол курстың оқытушылары тізіміне қосыңыз. Курсқа тек оқытушы рөлі бар адамды қосуға болады.

### 3.2. Деректерді сақтау мерзімі

Белгіленген мерзімі біткен немесе келісімін кері қайтарған студенттердің деректері анонимделеді. Әдепкі мерзім — 365 күн. Мұны мезгіл-мезгіл іске қосыңыз:

```
make retention
```

### 3.3. Резервтік көшірме

- Көшірме күн сайын, шифрланған түрде жасалады:
  ```
  docker compose --profile backup up -d backup
  ```
- Шифрлау кілтін (`BACKUP_PASSPHRASE`) серверден тыс, қауіпсіз жерде сақтаңыз. Кілтсіз көшірмені қалпына келтіру мүмкін емес.
- Қалпына келтіруді тоқсан сайын бөлек дерекқорға сынап көріңіз. Нұсқаулығы `docs/deploy/README.md` файлында.

### 3.4. Аудит журналы

Журналға кірулер (сәтті және сәтсіз), рөл өзгерістері, бағаны растау, деректерді экспорттау, баптауларды өзгерту жазылады. Журналды ешкім өзгерте де, өшіре де алмайды.

## 4. Орнату және жаңарту

Жүйені серверге орнату жолы `docs/deploy/README.md` файлында қадамдап жазылған:

- сервер талаптары;
- HTTPS баптау;
- `.env` файлы;
- Judge0 үшін керек cgroup v1.

## 5. Қауіпсіздік ережелері

- `.env` файлын және құпия кілттерді ешкімге жібермеңіз, репозиторийге салмаңыз.
- Әкімші аккаунтын тек әкімші жұмысына қолданыңыз.
- Пилоттан бұрын тәуелсіз ену тестін (pentest) сырттан жүргізіңіз. Бақылау тізімі: `docs/security/pentest-checklist.md`.
- Белгілі тәуекелдер мен оларды жабу жоспары: `docs/security/known-risks.md`.
